# 文書をチェックする

docs-lint により、見出しの構成、リンク切れ、必須文書や章の不足、用語の揺れ、要件 ID の整合などを確認できます。チェックは常に文書ルート全体に対して行います。

## チェックを実行する

1. ツールバーの [文書ツール] を押し、[チェック] タブを開きます。
2. [文書ルートを検証] を押します。
   コマンドパレットの「Lunascape Docs: 文書ルートを検証」でも実行できます。
3. 結果の一覧を確認します。

## 結果を読む

- 一覧の上の [この文書] / [すべて] で、表示する範囲を切り替えます。チェックの範囲自体は常に文書ルート全体です。
- 指摘には「エラー」「警告」「情報」「提案」の 4 段階があります。ツールバーの [文書ツール] には、エラーと警告の件数が表示されます。
- 指摘を押すと、該当する Markdown ソースの位置が VS Code のエディターで開きます。
- 文書ルート全体に関わる指摘（テスト文書の欠落など）は「文書ルート全体」の項目として表示され、位置は持ちません。
- 同じ指摘は VS Code の「問題」パネルにも表示されます。

## チェックする項目

[ルールを確認・変更] を押すと、有効なチェックの一覧と、それぞれの目的が表示されます。主な項目は次のとおりです。

| 項目 | 内容 |
|---|---|
| 見出しの構成 | H1 が 1 つあり、見出しレベルが途中で飛んでいないか |
| 内部リンク | リンク先の文書が存在し、文書ルートの外へ出ていないか |
| コードブロックの言語 | コードブロックに言語名が指定されているか |
| 必要なフォルダーと文書 | Standard Pack のプロファイルが求めるフォルダーと文書が揃っているか |
| 文書に必要な章 | 文書の種類ごとに必要な章があるか |
| 用語の統一 | 避ける表現を検出し、推奨する用語への統一を促す |
| 要件IDの命名と重複 | 要件 ID が命名規則に沿い、二重に定義されていないか |
| 要件IDの参照整合 | 設計、テスト、状況表などが参照する要件 ID が実在するか |
| 要件とテストの対応 | 要件 ID がテスト文書から参照されているか |

有効になる項目は、`lunascape-docs.json` で選んだ Standard Pack とプロファイル、および `docs-lint.config.json` で決まります。

> **ご注意**
>
> - 文書や設定を変更すると、前回の結果は「再検証が必要」になります。自動的に合格扱いにはなりません。もう一度 [文書ルートを検証] を押してください。
> - 保存していない変更はチェックに反映されません。先に保存してください。
> - チェックは端末内で決定的に実行されます。AI による評価や翻訳の結果がチェック結果に混ざることはありません。
