# שורש התיעוד ומוסכמות הקבצים

אלה הכללים שלפיהם Lunascape Docs מאתר מסמכים ובונה את ה‑INDEX. מערכת הקבצים עצמה היא המקור, ולכן אין צורך במרשם או בהגדרות בנייה.

## שורש התיעוד

- תיקיית `docs` הקרובה ביותר, או תיקייה שבה הונח `lunascape-docs.json`, הופכת לשורש התיעוד.
- אם הונח `lunascape-docs.json`, שם התיקייה אינו חייב להיות `docs`.
- פתיחת קובץ Markdown שאינו שייך לשום שורש תיעוד מציגה את התיקייה שלו כשורש תיעוד זמני.

## הקבצים המוצגים ב‑INDEX

- מוצגים קבצי `.md`, ‏`.markdown` ו‑`.mdx`. קבצים חדשים מוצגים תמיד, גם ללא front matter או נתוני ניווט.
- תיקיות שמתחילות ב‑`.`, ‏`node_modules`, והתיקיות שצוינו ב‑`ignoredDirectories` (ברירת המחדל: `99-archive`) אינן מוצגות.
- כל מה שנמצא תחת `i18n/` נחשב לתרגום ואינו מופיע בנפרד ב‑INDEX.

## דף השער של תיקייה

- קובץ `README.md` שיש בו תוכן (או `index.md` כשאין README) הוא דף השער של התיקייה. לחיצה על שם התיקייה ב‑INDEX פותחת אותו.
- קובץ `README.md` שמכיל front matter בלבד, ללא תוכן, נחשב "מתאר להגדרות בלבד" ואינו מוצג כדף. השתמשו בו כשלתיקייה דרושים רק כותרת או סדר.
- כאשר קיימים גם `README.md` וגם `index.md`, ‏`README.md` גובר.

## שפת ברירת המחדל וגרסאות מתורגמות

- מסמכים בשפת ברירת המחדל (מסמכי המקור) נשארים במקומם.
- התרגום מונח בתיקייה `i18n/<שפה>/` שלצד המסמך, תחת אותו שם קובץ. בנייה מחדש של מבנה התיקיות תחת `i18n/` אינה מזוהה.
- זהו המקום היחיד שממנו נפתר התרגום. אותו קובץ שהונח במקום אחר הוא קובץ יתום, שאינו נחשב לתרגום של אף מסמך.

```text
docs/
  lunascape-docs.json
  README.md                  ← דף השער של שורש התיעוד (דף הפתיחה)
  i18n/en/README.md          ← הגרסה האנגלית שלו
  01-product/
    README.md                ← דף השער של התיקייה
    requirements.md
    i18n/en/README.md        ← הגרסאות האנגליות של שני המסמכים שלמעלה
    i18n/en/requirements.md
  99-archive/                ← מוחרג מה‑INDEX כברירת מחדל
```

## על אודות `_meta.json`

הקובץ `_meta.json` של Nextra אינו משמש לניווט. קבצים קיימים אינם משתנים ואינם נמחקים. בעתיד הם יטופלו רק באמצעות פעולה מפורשת של ייבוא וייצוא.
