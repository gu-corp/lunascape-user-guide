# Налаштування навігаційних даних

Назва та порядок, які показує INDEX, записуються в YAML front matter кожного документа. Документи показуються й без нього — використовуються заголовок (H1) і порядок за іменами файлів.

## Назва та порядок документа

Напишіть на початку документа таке.

```yaml
---
navigation:
  title: Початок роботи
  order: 200
---
```

| Поле | Значення |
|---|---|
| `navigation.title` | Назва, яку показує INDEX. Якщо пропущено, використовується H1, а якщо його немає — ім'я файлу |
| `navigation.order` | Ціле число, що визначає порядок, за зростанням. Якщо пропущено, діє стабільний типовий порядок (за іменем файлу) |

> **Порада**
>
> - Задавайте `order` з кроком 100 — 100, 200, 300, — щоб згодом вставити між ними 150.
> - Відсутні, хибні або повторювані значення `order` ніколи не приховують документ.
> - Зміна порядку в INDEX сама записує `navigation.order`; писати його вручну не потрібно.

## Назва та порядок папки

Назва та порядок папки належать front matter її файлу `README.md` (або `index.md`, якщо README немає). Титульна сторінка може й не мати основного тексту.

```yaml
---
navigation:
  title: Планування продукту
  order: 100
---
```

Папка без титульної сторінки показується з іменем папки та типовим порядком. Якщо зміна назви або порядку в INDEX цього потребує, створюється `README.md`, що містить лише front matter. Саме лише читання ніколи не створює файл.

## Поводження з перекладами

- Порядок і роль папки (титульна сторінка чи лише налаштування) визначає тільки документ мовою за замовчуванням.
- Переклад може перевизначити лише `navigation.title`. Якщо оригінал документа має основний текст, як назва використовується також H1 перекладу.
- Сам лише переклад ніколи не додає сторінку.

## Порядок і згортання дочірніх елементів

На титульній сторінці папки визначено `navigation.children.sort` і `navigation.children.defaultCollapsed` — вони задають порядок безпосередніх дочірніх елементів і те, чи будуть вони спочатку згорнуті. Читання та редагування їх у VS Code заплановано.
