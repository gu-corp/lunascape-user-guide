# Проверка документов

docs-lint проверяет структуру заголовков, неработающие ссылки, отсутствие обязательных документов и разделов, разнобой в терминологии, согласованность идентификаторов требований и другое. Проверка всегда охватывает весь корень документации.

## Выполнение проверки

1. Нажмите [Инструменты документа] на панели инструментов и откройте вкладку [Проверка].
2. Нажмите [Проверить корень документации].
   Проверку можно также запустить командой «Lunascape Docs: Проверить корень документации» из палитры команд.
3. Просмотрите список замечаний.

## Чтение результатов

- Переключатель [Этот документ] / [Все] над списком меняет то, что показано. Сама проверка всегда охватывает весь корень документации.
- Замечания имеют четыре уровня: «ошибка», «предупреждение», «сведения» и «подсказка». На кнопке [Инструменты документа] на панели инструментов показано количество ошибок и предупреждений.
- Нажмите замечание, чтобы открыть соответствующее место в исходном тексте Markdown в редакторе VS Code.
- Замечания, относящиеся ко всему корню документации (например, отсутствие тестового документа), отображаются как пункты «Весь корень документации» и не имеют положения в тексте.
- Те же замечания отображаются и на панели «Проблемы» в VS Code.

## Что проверяется

Нажмите [Просмотреть и изменить правила], чтобы увидеть список действующих проверок и назначение каждой из них. Основные из них:

| Проверка | Содержание |
|---|---|
| Структура заголовков | Есть ровно один H1, и уровни заголовков не пропускаются |
| Внутренние ссылки | Документы по ссылкам существуют и не выходят за пределы корня документации |
| Язык блока кода | Для блоков кода указано название языка |
| Обязательные папки и документы | Папки и документы, требуемые профилем Standard Pack, на месте |
| Обязательные разделы документа | У документа каждого типа есть необходимые разделы |
| Единство терминологии | Выявляются нежелательные выражения и предлагаются рекомендуемые термины |
| Именование и дубликаты идентификаторов требований | Идентификаторы требований соответствуют правилу именования и не определены дважды |
| Согласованность ссылок на идентификаторы требований | Идентификаторы требований, на которые ссылаются проектные и тестовые документы, таблицы состояния, существуют |
| Соответствие требований и тестов | На идентификаторы требований есть ссылки из тестовых документов |

Какие проверки включены, зависит от Standard Pack и профиля, выбранных в `lunascape-docs.json`, а также от `docs-lint.config.json`.

> **Примечание**
>
> - После изменения документа или настройки прежний результат помечается как «требуется повторная проверка». Автоматически ничего не считается пройденным — нажмите [Проверить корень документации] еще раз.
> - Несохраненные изменения в проверку не попадают. Сначала сохраните их.
> - Проверка выполняется на устройстве и детерминированно. Результаты оценки ИИ и перевода никогда не смешиваются с результатами проверки.
