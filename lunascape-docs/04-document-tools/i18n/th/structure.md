# รากเอกสารและข้อกำหนดของไฟล์

กฎที่ Lunascape Docs ใช้ในการค้นหาเอกสารและประกอบ INDEX ระบบไฟล์เป็นต้นฉบับโดยตรง จึงไม่ต้องมีบัญชีรายการหรือการตั้งค่าสำหรับการบิลด์

## รากเอกสาร

- โฟลเดอร์ `docs` ที่ใกล้ที่สุด หรือโฟลเดอร์ที่วาง `lunascape-docs.json` ไว้ จะกลายเป็นรากเอกสาร
- หากวาง `lunascape-docs.json` ไว้ ชื่อโฟลเดอร์ไม่จำเป็นต้องเป็น `docs`
- เมื่อเปิดไฟล์ Markdown ที่ไม่ได้อยู่ในรากเอกสารใด จะแสดงโฟลเดอร์นั้นเป็นรากเอกสารชั่วคราว

## ไฟล์ที่แสดงใน INDEX

- แสดงไฟล์ `.md`, `.markdown` และ `.mdx` ไฟล์ใหม่จะแสดงเสมอ แม้ไม่มี front matter หรือข้อมูลการนำทาง
- โฟลเดอร์ที่ขึ้นต้นด้วย `.` โฟลเดอร์ `node_modules` และโฟลเดอร์ที่ระบุไว้ใน `ignoredDirectories` (ค่าเริ่มต้นคือ `99-archive`) จะไม่แสดง
- ทุกอย่างที่อยู่ใต้ `i18n/` จะถือเป็นคำแปล และจะไม่แสดงแยกต่างหากใน INDEX

## หน้าปกของโฟลเดอร์

- `README.md` ที่มีเนื้อหา (หรือ `index.md` เมื่อไม่มี README) จะเป็นหน้าปกของโฟลเดอร์นั้น เมื่อกดชื่อโฟลเดอร์ใน INDEX หน้าปกจะเปิดขึ้น
- `README.md` ที่มีเพียง front matter โดยไม่มีเนื้อหา จะถือเป็น "ตัวระบุสำหรับการตั้งค่าเท่านั้น" และจะไม่แสดงเป็นหน้า ใช้เมื่อต้องการกำหนดเพียงชื่อหรือลำดับของโฟลเดอร์
- เมื่อมีทั้ง `README.md` และ `index.md` จะใช้ `README.md` ก่อน

## ภาษาเริ่มต้นและคำแปล

- เอกสารภาษาเริ่มต้น (เอกสารต้นฉบับ) ให้วางไว้ที่เดิม
- คำแปลให้วางไว้ใน `i18n/<ภาษา>/` ในโฟลเดอร์เดียวกับเอกสารต้นฉบับ โดยใช้ชื่อไฟล์เดียวกัน การสร้างโครงสร้างโฟลเดอร์ขึ้นใหม่ใต้ `i18n/` จะไม่ถูกรับรู้
- ตำแหน่งที่ใช้ค้นหาคำแปลมีเพียงแห่งเดียวเท่านั้น ไฟล์ชื่อเดียวกันที่วางไว้ที่อื่นจะเป็นไฟล์กำพร้าที่ไม่ถูกถือเป็นคำแปลของเอกสารใดเลย

```text
docs/
  lunascape-docs.json
  README.md                  ← หน้าปกของรากเอกสาร (หน้าเริ่มต้น)
  i18n/en/README.md          ← ฉบับภาษาอังกฤษของหน้านั้น
  01-product/
    README.md                ← หน้าปกของโฟลเดอร์
    requirements.md
    i18n/en/README.md        ← ฉบับภาษาอังกฤษของสองเอกสารข้างต้น
    i18n/en/requirements.md
  99-archive/                ← ถูกแยกออกจาก INDEX ตามค่าเริ่มต้น
```

## เกี่ยวกับ `_meta.json`

`_meta.json` ของ Nextra ไม่ได้ใช้สำหรับการนำทาง ไฟล์ที่มีอยู่จะไม่ถูกแก้ไขหรือลบ ในอนาคตจะใช้งานเฉพาะกับฟังก์ชันนำเข้า/ส่งออกที่ระบุไว้อย่างชัดเจนเท่านั้น
