# การตรวจสอบเอกสาร

docs-lint ช่วยตรวจสอบโครงสร้างหัวข้อ ลิงก์เสีย เอกสารหรือหัวข้อที่จำเป็นแต่ขาดหายไป ความไม่สอดคล้องของคำศัพท์ ความสอดคล้องของรหัสข้อกำหนด และอื่น ๆ การตรวจสอบจะครอบคลุมรากเอกสารทั้งหมดเสมอ

## เรียกใช้การตรวจสอบ

1. กด [เครื่องมือเอกสาร] บนแถบเครื่องมือ แล้วเปิดแท็บ [ตรวจสอบ]
2. กด [ตรวจสอบรากเอกสาร]
   นอกจากนี้ยังเรียกใช้ได้จาก “Lunascape Docs: ตรวจสอบรากเอกสาร” ในแผงคำสั่ง
3. ตรวจดูรายการผลลัพธ์

## อ่านผลลัพธ์

- ใช้ [เอกสารนี้] / [ทั้งหมด] ที่อยู่เหนือรายการเพื่อสลับขอบเขตที่แสดง ส่วนขอบเขตของการตรวจสอบเองนั้นครอบคลุมรากเอกสารทั้งหมดเสมอ
- ข้อชี้แนะมี 4 ระดับ ได้แก่ “ข้อผิดพลาด” “คำเตือน” “ข้อมูล” และ “ข้อเสนอแนะ” โดย [เครื่องมือเอกสาร] บนแถบเครื่องมือจะแสดงจำนวนข้อผิดพลาดและคำเตือน
- เมื่อกดที่ข้อชี้แนะ ตำแหน่งที่เกี่ยวข้องในซอร์ส Markdown จะเปิดขึ้นในตัวแก้ไขของ VS Code
- ข้อชี้แนะที่เกี่ยวกับรากเอกสารทั้งหมด (เช่น เอกสารทดสอบที่ขาดหายไป) จะแสดงเป็นรายการ “รากเอกสารทั้งหมด” และไม่มีตำแหน่งกำกับ
- ข้อชี้แนะเดียวกันนี้จะแสดงในแผง “ปัญหา” ของ VS Code ด้วย

## รายการที่ตรวจสอบ

เมื่อกด [ตรวจสอบและแก้ไขกฎ] จะแสดงรายการการตรวจสอบที่เปิดใช้งานอยู่พร้อมวัตถุประสงค์ของแต่ละรายการ รายการหลักมีดังนี้

| รายการ | เนื้อหา |
|---|---|
| โครงสร้างหัวข้อ | มี H1 หนึ่งรายการ และระดับหัวข้อไม่ข้ามลำดับ |
| ลิงก์ภายใน | เอกสารปลายทางมีอยู่จริง และไม่ออกไปนอกรากเอกสาร |
| ภาษาของบล็อกโค้ด | บล็อกโค้ดระบุชื่อภาษาไว้หรือไม่ |
| โฟลเดอร์และเอกสารที่จำเป็น | มีโฟลเดอร์และเอกสารครบตามที่โปรไฟล์ของ Standard Pack กำหนดหรือไม่ |
| หัวข้อที่จำเป็นในเอกสาร | เอกสารแต่ละประเภทมีหัวข้อที่จำเป็นหรือไม่ |
| ความสอดคล้องของคำศัพท์ | ตรวจจับถ้อยคำที่ควรหลีกเลี่ยง และแนะนำให้ใช้คำศัพท์ที่แนะนำอย่างสม่ำเสมอ |
| การตั้งชื่อและการซ้ำของรหัสข้อกำหนด | รหัสข้อกำหนดเป็นไปตามกฎการตั้งชื่อ และไม่ถูกกำหนดซ้ำสองครั้ง |
| ความสอดคล้องของการอ้างอิงรหัสข้อกำหนด | รหัสข้อกำหนดที่อ้างอิงจากงานออกแบบ การทดสอบ และตารางสถานะมีอยู่จริงหรือไม่ |
| ความสัมพันธ์ระหว่างข้อกำหนดกับการทดสอบ | รหัสข้อกำหนดถูกอ้างอิงจากเอกสารทดสอบหรือไม่ |

รายการที่เปิดใช้งานขึ้นอยู่กับ Standard Pack และโปรไฟล์ที่เลือกไว้ใน `lunascape-docs.json` รวมถึง `docs-lint.config.json`

> **ข้อควรระวัง**
>
> - เมื่อแก้ไขเอกสารหรือการตั้งค่า ผลลัพธ์ครั้งก่อนจะกลายเป็น “ต้องตรวจสอบใหม่” และจะไม่ถือว่าผ่านโดยอัตโนมัติ กรุณากด [ตรวจสอบรากเอกสาร] อีกครั้ง
> - การเปลี่ยนแปลงที่ยังไม่ได้บันทึกจะไม่ถูกนำมาใช้ในการตรวจสอบ กรุณาบันทึกก่อน
> - การตรวจสอบทำงานภายในเครื่องอย่างเป็นผลลัพธ์แน่นอน ผลการประเมินหรือคำแปลจาก AI จะไม่ปะปนเข้ามาในผลการตรวจสอบ
