# 检查文档

通过 docs-lint，可以检查标题结构、失效链接、必需文档或章节的缺失、术语不统一、需求 ID 的一致性等。检查始终针对整个文档根目录进行。

## 执行检查

1. 按工具栏的 [文档工具]，打开 [检查] 标签页。
2. 按 [检查文档根目录]。
   也可以在命令面板中执行“Lunascape Docs: 检查文档根目录”。
3. 查看结果列表。

## 阅读结果

- 用列表上方的 [本文档] / [全部] 切换显示范围。检查本身的范围始终是整个文档根目录。
- 提示分为“错误”“警告”“信息”“建议”四个级别。工具栏的 [文档工具] 会显示错误和警告的数量。
- 按下某条提示，会在 VS Code 编辑器中打开对应的 Markdown 源位置。
- 涉及整个文档根目录的提示（例如缺少测试文档）会显示为“整个文档根目录”项目，不带位置。
- 相同的提示也会显示在 VS Code 的“问题”面板中。

## 检查的项目

按 [查看和更改规则]，会显示已启用的检查列表以及各自的用途。主要项目如下。

| 项目 | 内容 |
|---|---|
| 标题结构 | 是否只有一个 H1，标题级别中途是否跳级 |
| 内部链接 | 链接目标文档是否存在，是否超出文档根目录 |
| 代码块的语言 | 代码块是否指定了语言名 |
| 必需的文件夹和文档 | Standard Pack 的配置文件所要求的文件夹和文档是否齐全 |
| 文档必需的章节 | 各类文档是否具备必需的章节 |
| 术语统一 | 检测应避免的表述，促使统一为推荐术语 |
| 需求 ID 的命名与重复 | 需求 ID 是否符合命名规则，是否被重复定义 |
| 需求 ID 的引用一致性 | 设计、测试、状态表等引用的需求 ID 是否实际存在 |
| 需求与测试的对应 | 需求 ID 是否被测试文档引用 |

启用哪些项目，取决于在 `lunascape-docs.json` 中选择的 Standard Pack 和配置文件，以及 `docs-lint.config.json`。

> **注意**
>
> - 更改文档或设置后，上一次的结果会变为“需要重新检查”。不会自动视为通过。请再次按 [检查文档根目录]。
> - 未保存的更改不会反映到检查中。请先保存。
> - 检查在本机上确定性地执行。AI 的评估结果和翻译结果不会混入检查结果。
