# 檢查文件

docs-lint 可檢查標題結構、連結失效、必要文件或章節的缺漏、用語不一致、需求 ID 的一致性等。檢查一律以整個文件根目錄為對象。

## 執行檢查

1. 按下工具列的 [文件工具]，開啟 [檢查] 分頁。
2. 按下 [驗證文件根目錄]。
   也可以在命令選擇區執行「Lunascape Docs: 驗證文件根目錄」。
3. 確認結果清單。

## 閱讀結果

- 以清單上方的 [本文件] / [全部] 切換顯示範圍。檢查本身的範圍一律是整個文件根目錄。
- 指摘分為「錯誤」「警告」「資訊」「建議」4 個等級。工具列的 [文件工具] 會顯示錯誤與警告的件數。
- 按下指摘，即可在 VS Code 的編輯器中開啟對應的 Markdown 原始碼位置。
- 與整個文件根目錄有關的指摘（例如缺少測試文件），會顯示為「整個文件根目錄」項目，不具有位置。
- 相同的指摘也會顯示在 VS Code 的「問題」面板中。

## 檢查的項目

按下 [確認與變更規則]，會顯示已啟用的檢查清單及各項目的目的。主要項目如下。

| 項目 | 內容 |
|---|---|
| 標題結構 | 是否有 1 個 H1，標題層級中途是否有跳號 |
| 內部連結 | 連結目標文件是否存在，是否超出文件根目錄之外 |
| 程式碼區塊的語言 | 程式碼區塊是否指定了語言名稱 |
| 必要的資料夾與文件 | Standard Pack 的設定檔所要求的資料夾與文件是否齊備 |
| 文件必要的章節 | 各類文件是否具備必要的章節 |
| 用語統一 | 偵測應避免的表達，促使統一為建議用語 |
| 需求 ID 的命名與重複 | 需求 ID 是否符合命名規則，是否重複定義 |
| 需求 ID 的參照一致性 | 設計、測試、狀況表等所參照的需求 ID 是否實際存在 |
| 需求與測試的對應 | 需求 ID 是否從測試文件被參照 |

啟用的項目取決於在 `lunascape-docs.json` 中選擇的 Standard Pack 與設定檔，以及 `docs-lint.config.json`。

> **注意**
>
> - 變更文件或設定後，上次的結果會變成「需要重新驗證」。不會自動視為合格。請再次按下 [驗證文件根目錄]。
> - 未儲存的變更不會反映在檢查中。請先儲存。
> - 檢查會在本機以決定性的方式執行。AI 的評估或翻譯結果不會混入檢查結果中。
