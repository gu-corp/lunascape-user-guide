# Публікація власних документів у Web

Документи власного репозиторію можна опублікувати як вебсайт на GitHub Pages або на будь-якому статичному хостингу. Є два способи. Ці кроки призначені для розробників, які можуть клонувати репозиторій Lunascape Docs і користуватися `npm`.

## Спосіб 1: розмістити два файли переглядача

Розгортається лише сам переглядач (`index.html` і `lsdoc.js`), а документи завантажуються з GitHub. Самі документи не входять до складу сайту, тому цей спосіб безпечний і для закритих репозиторіїв (читачі входять через GitHub).

1. У репозиторії Lunascape Docs виконайте таку команду.

   ```sh
   npm run build:viewer
   ```

   У `dist/viewer/` буде створено `index.html` і `lsdoc.js`.
2. Покладіть ці два файли до папки `docs/` того репозиторію, який хочете опублікувати.
3. Увімкніть GitHub Pages.

Корінь документації для показу визначається в такому порядку.

1. Параметр `source` всередині `index.html`
2. `repository`, вказаний у `lunascape-docs.json` у тій самій папці
3. Припущення з URL `*.github.io` та структури гілок

## Спосіб 2: експортувати статичний сайт разом із документами

Переглядач і файли документів експортуються разом, і результат розміщується на хостингу як є.

```sh
npm run export:web -- --root ./docs --out ./dist-site
```

Виводяться повний набір файлів переглядача, документи з `docs/`, файл списку `lunascape-docs-manifest.json` і `.nojekyll`. Розмістіть результат на S3 або GitHub Pages, щоб опублікувати його. Приклад автоматичної публікації через GitHub Actions див. у файлі `examples/workflows/publish-docs-pages.yml` у репозиторії.

> **Примітка**
>
> - **Не експортуйте документи закритого репозиторію на GitHub Pages.** Поза межами Enterprise Cloud сторінки GitHub Pages доступні всім. Якщо потрібен обмежений доступ, скористайтеся способом 1 і дозвольте читачам входити через GitHub.
> - Відкриття `index.html` безпосередньо через `file://` не працює, оскільки браузер забороняє завантаження сусідніх файлів і виконання модулів ES. Для перевірки на своєму комп'ютері скористайтеся версією для VS Code або HTTP-сервером.
> - Бібліотеки рендерингу для TikZ, Vega-Lite, Markmap, WaveDrom, Svgbob і Penrose завантажуються під час відображення. Разом з експортованим сайтом розмістіть також папку `vendor/`.
