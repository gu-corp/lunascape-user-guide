# نشر مستنداتك على الويب

يمكنك نشر مستندات مستودعك الخاص كموقع ويب على GitHub Pages أو على أي استضافة ثابتة. توجد طريقتان للنشر. هذه الخطوات موجَّهة إلى المطوّرين الذين يمكنهم استنساخ مستودع Lunascape Docs واستخدام `npm`.

## الطريقة 1: وضع ملفَّي العارض

في هذه الطريقة تضع العارض وحده (`index.html` و`lsdoc.js`)، وتُحمَّل المستندات من GitHub. المستندات نفسها ليست جزءًا من الموقع، لذا فهذه الطريقة آمنة مع المستودعات الخاصة (يسجّل القارئ الدخول عبر GitHub).

1. نفِّذ الأمر التالي في مستودع Lunascape Docs.

   ```sh
   npm run build:viewer
   ```

   يُنشَأ الملفان `index.html` و`lsdoc.js` في `dist/viewer/`.
2. ضع الملفين في مجلد `docs/` الخاص بالمستودع الذي تريد نشره.
3. فعِّل GitHub Pages.

يُحدَّد جذر التوثيق المعروض بالترتيب التالي.

1. الإعداد `source` داخل `index.html`
2. الحقل `repository` في ملف `lunascape-docs.json` الموجود في المجلد نفسه
3. الاستنتاج من عنوان `*.github.io` ومن بنية الفروع

## الطريقة 2: تصدير موقع ثابت يتضمّن المستندات

في هذه الطريقة تُصدِّر العارض وملفات المستندات معًا، وتستضيف الناتج كما هو.

```sh
npm run export:web -- --root ./docs --out ./dist-site
```

يحتوي الناتج على العارض كاملًا، والمستندات الموجودة تحت `docs/`، وملف الفهرس `lunascape-docs-manifest.json`، وملف `.nojekyll`. ضع وجهة الإخراج على S3 أو على GitHub Pages لنشرها. للاطّلاع على مثال للنشر التلقائي عبر GitHub Actions، راجع الملف `examples/workflows/publish-docs-pages.yml` في المستودع.

> **ملاحظة**
>
> - **لا تُصدِّر مستندات مستودع خاص وتضعها على GitHub Pages.** فصفحات GitHub Pages خارج Enterprise Cloud يمكن لأي شخص الاطّلاع عليها. إذا كنت بحاجة إلى نشر محدود، فاستخدم الطريقة 1 ودع القرّاء يسجّلون الدخول عبر GitHub.
> - لا يعمل فتح `index.html` مباشرةً عبر `file://`، لأن المتصفح يمنع تحميل الملفات المجاورة وتشغيل وحدات ES بهذه الطريقة. للتحقّق محليًا، استخدم إصدار VS Code أو خادم HTTP.
> - تُحمَّل مكتبات الرسم الخاصة بـ TikZ وVega-Lite وMarkmap وWaveDrom وSvgbob وPenrose عند العرض. في الموقع المُصدَّر، ضع مجلد `vendor/` معه أيضًا.
