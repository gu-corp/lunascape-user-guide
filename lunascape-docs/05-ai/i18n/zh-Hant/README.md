# 將工作交給 AI

Lunascape Docs 不會呼叫語言模型。它準備好**脈絡、工具與驗證**，翻譯、校對與撰寫的實際執行則交給您慣用的 AI。

## 基本概念

| 產品提供的內容 | 內容 |
|---|---|
| 脈絡 | 文件的規約（翻譯版的存放位置、front matter、文件標準、詞彙表），以及目標文件的位置 |
| 作業工具 | 未翻譯與需更新的帳冊、文件的讀寫、從範本建立 |
| 事後檢查 | 以 docs-lint 驗證、涵蓋狀況與新鮮度的差異 |

指示文中不含文件本文。AI 會自行讀取檔案、自行撰寫、自行驗證。

## 交付工作

1. 按下工具列的 [文件工具]，開啟 [AI] 索引標籤。
2. 從 [作業] 中選擇要交付的工作。
3. 輸入必要的項目（目標語言、主題）。
4. 按下 [交付此作業]。
   VS Code 的終端機會開啟，您選擇的 AI 接收指示並開始作業。

> **提示**
>
> Claude Code 的工作階段會隨附作業工具（MCP 伺服器 `lunascape-docs`）。工作階段可以自行取得未翻譯與需更新的清單、執行 docs-lint，並在翻譯後記錄新鮮度。

## 確認結果

| 提供者的型態 | 結果的落點 |
|---|---|
| 工作階段型（Claude Code、Codex） | 直接寫入工作樹。請**以 Git 的差異確認** |
| API 型（VS Code 的語言模型、Anthropic、OpenAI 相容） | 每次回傳一份文件的建議。以 [開啟差異] 確認，再以 [儲存] 寫入 |

### 確認 API 型的建議

以 API 型執行後，建議會送到 [AI] 索引標籤。

1. 按下 [開啟差異]，確認與目前內容的差別。
2. 沒問題就按下 [儲存]。若是翻譯，也會一併記錄新鮮度。要放棄時請按 [捨棄]。
   若要中途停止產生，請按 [中止]。

> **注意**
>
> - Lunascape Docs 不會執行 Git 的暫存或提交。變更請務必以差異確認。
> - 在未信任的工作區，以及在文件根目錄外的暫時資料夾顯示中，無法交付工作。
