# העברת עבודה ל-AI

‏Lunascape Docs אינו קורא למודל שפה. הוא מכין **הקשר, כלים ובדיקות**, ומשאיר את ביצוע התרגום, ההגהה והכתיבה ל-AI שבו אתם משתמשים.

## העיקרון

| מה המוצר מספק | תוכן |
|---|---|
| הקשר | מוסכמות התיעוד (מקום שמירתן של גרסאות התרגום, front matter, תקן המסמכים, מילון המונחים) ומיקומו של המסמך המבוקש |
| כלי עבודה | פנקס התרגומים החסרים והדורשים עדכון, קריאה וכתיבה של מסמכים, יצירה מתוך תבנית |
| בדיקה שלאחר מעשה | אימות באמצעות docs-lint, והפרש הכיסוי והעדכניות |

ההוראה אינה כוללת את גוף המסמך. ה-AI קורא את הקבצים בעצמו, כותב בעצמו ומאמת בעצמו.

## העברת המשימה

1. בסרגל הכלים לחצו על [כלי מסמכים] ופתחו את הלשונית [AI].
2. בחרו ב-[משימה] את העבודה שברצונכם להעביר.
3. מלאו את הפרטים הנדרשים (שפת היעד, הנושא).
4. לחצו על [מסירת המשימה].
   טרמינל של VS Code נפתח, וה-AI שבחרתם מקבל את ההוראה ומתחיל לעבוד.

> **טיפ**
>
> לשיחה של Claude Code מתלווים כלי עבודה (שרת ה-MCP‏ `lunascape-docs`). השיחה יכולה להביא בעצמה את רשימת התרגומים החסרים והדורשים עדכון, להריץ את docs-lint ולרשום את העדכניות לאחר התרגום.

## בדיקת התוצאה

| צורת הספק | היכן נוחתת התוצאה |
|---|---|
| מבוסס שיחה (Claude Code‏, Codex) | כותב ישירות לעץ העבודה. **בדקו זאת בהשוואת ה-Git** |
| מבוסס API (מודלי השפה של VS Code‏, Anthropic, תואמי OpenAI) | מחזיר הצעה למסמך אחד בכל פעם. בדקו אותה בעזרת [פתיחת השוואה] וכתבו אותה בעזרת [שמירה] |

### בדיקת הצעה של ספק API

בהרצה עם ספק API מגיעה הצעה ללשונית [AI].

1. לחצו על [פתיחת השוואה] ובדקו את ההבדל מהתוכן הנוכחי.
2. אם ההצעה מתאימה, לחצו על [שמירה]. בתרגום נרשמת גם העדכניות. כדי לוותר, לחצו על [השלכה].
   כדי להפסיק את היצירה באמצע, לחצו על [עצירה].

> **שימו לב**
>
> - ‏Lunascape Docs אינו מבצע העלאה לאזור ההכנה (stage) או קיבוע (commit) ב-Git. בדקו את השינויים תמיד בהשוואה.
> - בסביבת עבודה שאינה מהימנה, וכן בתצוגת תיקייה זמנית שמחוץ לשורש התיעוד, לא ניתן להעביר משימה.
