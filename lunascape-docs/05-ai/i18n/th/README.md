# ส่งงานให้ AI

Lunascape Docs ไม่เรียกใช้โมเดลภาษา แต่จะเตรียม **บริบท เครื่องมือ และการตรวจทาน** ไว้ให้ แล้วปล่อยให้ AI ที่คุณใช้อยู่เป็นผู้แปล ตรวจแก้ และเขียนเอง

## แนวคิด

| สิ่งที่ผลิตภัณฑ์เตรียมให้ | เนื้อหา |
|---|---|
| บริบท | ข้อกำหนดของเอกสาร (ที่เก็บฉบับแปล front matter มาตรฐานเอกสาร อภิธานศัพท์) และตำแหน่งของเอกสารเป้าหมาย |
| เครื่องมือทำงาน | บัญชีรายการที่ยังไม่ได้แปลและต้องอัปเดต การอ่านและเขียนเอกสาร การสร้างจากเทมเพลต |
| การตรวจสอบภายหลัง | การตรวจสอบด้วย docs-lint และส่วนต่างของความครอบคลุมกับความใหม่ |

ข้อความสั่งงานไม่มีเนื้อหาของเอกสารรวมอยู่ด้วย AI จะอ่านไฟล์เอง เขียนเอง และตรวจสอบเอง

## ส่งงาน

1. กด [เครื่องมือเอกสาร] บนแถบเครื่องมือ แล้วเปิดแท็บ [AI]
2. เลือกงานที่ต้องการส่งจาก [งาน]
3. กรอกรายการที่จำเป็น (ภาษาเป้าหมาย หัวข้อ)
4. กด [ส่งงานนี้]
   เทอร์มินัลของ VS Code จะเปิดขึ้น และ AI ที่เลือกไว้จะรับคำสั่งแล้วเริ่มทำงาน

> **เคล็ดลับ**
>
> เซสชันของ Claude Code จะมีเครื่องมือทำงาน (เซิร์ฟเวอร์ MCP `lunascape-docs`) ติดไปด้วย เซสชันจึงดึงรายการที่ยังไม่ได้แปลและต้องอัปเดต เรียกใช้ docs-lint และบันทึกความใหม่หลังแปลได้ด้วยตนเอง

## การตรวจสอบผลลัพธ์

| รูปแบบของผู้ให้บริการ | ปลายทางของผลลัพธ์ |
|---|---|
| แบบเซสชัน (Claude Code, Codex) | เขียนลงในทรีงานโดยตรง กรุณา **ตรวจสอบด้วยส่วนต่างของ Git** |
| แบบ API (โมเดลภาษาของ VS Code, Anthropic, ที่เข้ากันได้กับ OpenAI) | ส่งข้อเสนอกลับมาทีละเอกสาร ตรวจสอบด้วย [เปิดส่วนต่าง] แล้วเขียนด้วย [บันทึก] |

### ตรวจสอบข้อเสนอแบบ API

เมื่อเรียกใช้แบบ API ข้อเสนอจะมาถึงที่แท็บ [AI]

1. กด [เปิดส่วนต่าง] แล้วตรวจดูความแตกต่างจากเนื้อหาปัจจุบัน
2. หากไม่มีปัญหา ให้กด [บันทึก] กรณีเป็นคำแปลจะมีการบันทึกความใหม่ด้วย หากต้องการยกเลิก ให้กด [ทิ้ง]
   หากต้องการหยุดการสร้างระหว่างทาง ให้กด [หยุด]

> **หมายเหตุ**
>
> - Lunascape Docs จะไม่ทำการ stage หรือ commit ใน Git กรุณาตรวจสอบการเปลี่ยนแปลงด้วยส่วนต่างทุกครั้ง
> - ในพื้นที่ทำงานที่ไม่เชื่อถือ และในการแสดงโฟลเดอร์ชั่วคราวที่อยู่นอกรากเอกสาร จะส่งงานไม่ได้
