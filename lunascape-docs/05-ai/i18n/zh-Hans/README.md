# 将工作交给 AI

Lunascape Docs 不会调用语言模型。它准备好**上下文、工具和检查**，把翻译、校对和撰写的执行交给你使用的 AI。

## 思路

| 产品提供的内容 | 内容 |
|---|---|
| 上下文 | 文档规约（翻译版的存放位置、front matter、文档标准、术语表）以及目标文档的位置 |
| 工作工具 | 未翻译和需更新的台账、文档的读写、从模板创建 |
| 事后检查 | docs-lint 的校验、覆盖情况与新鲜度的差异 |

指令中不包含文档正文。AI 自己读取文件、自己撰写、自己校验。

## 交付工作

1. 按工具栏中的 [文档工具]，打开 [AI] 选项卡。
2. 从 [任务] 中选择要交付的工作。
3. 填写所需项目（目标语言、主题）。
4. 按 [交付此任务]。
   VS Code 的终端会打开，所选的 AI 接收指令并开始工作。

> **提示**
>
> Claude Code 的会话会随附工作工具（MCP 服务器 `lunascape-docs`）。会话可以自行获取未翻译和需更新的列表、运行 docs-lint、并在翻译后记录新鲜度。

## 确认结果

| 提供方形态 | 结果的落点 |
|---|---|
| 会话型（Claude Code、Codex） | 直接写入工作树。请**在 Git 的差异中确认** |
| API 型（VS Code 的语言模型、Anthropic、OpenAI 兼容） | 每次返回一个文档的建议。用 [打开差异] 确认，用 [保存] 写入 |

### 确认 API 型的建议

以 API 型运行时，建议会送到 [AI] 选项卡。

1. 按 [打开差异]，确认与当前内容的差别。
2. 没有问题就按 [保存]。翻译时还会记录新鲜度。要放弃时按 [丢弃]。
   要中途停止生成，请按 [停止]。

> **注意**
>
> - Lunascape Docs 不会执行 Git 的暂存或提交。更改请务必在差异中确认。
> - 在不受信任的工作区，以及在文档根目录之外的临时文件夹显示中，无法交付工作。
